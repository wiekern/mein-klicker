# MeinKlicker

一个简单的 Android 自动点击器：按顺序自动点击、保存点击方案，还支持"亲手点第一下、后面自动完成"的手动触发模式。

## 功能

- 按顺序自动点击多个位置，支持步骤间隔和循环
- 保存 / 管理点击方案（拖动悬浮标记设置位置）
- 手动触发：亲手点击第一个位置后，自动完成后续点击

只需要开启**无障碍服务**这一项权限；悬浮窗由无障碍服务托管，不需要单独的悬浮窗权限。

## 下载安装

1. 在 [Releases](https://github.com/wiekern/mein-klicker/releases) 页面下载最新的 `MeinKlicker-vX.Y.Z.apk` 到手机；
2. 在手机上点开 APK 安装。第一次安装时，系统会提示是否允许浏览器 / 文件管理器"安装未知应用"，选择允许；
3. **Android 13 及以上**：这样安装的应用默认不能开启无障碍服务（"受限制的设置"）。开启前先到 **设置 → 应用 → MeinKlicker → 右上角 ⋮ → 允许受限制的设置**。如果菜单里没有这一项，先去无障碍设置里尝试开启一次，被系统拦下后再回来就会出现；不同手机的菜单位置可能略有不同。

需要 Android 8.0 及以上。

## 首次设置

打开 App，主界面顶部的状态卡逐项处理：

1. **无障碍服务** → 去开启 → 在系统列表中找到"MeinKlicker 自动点击"并打开（如提示"应用受限"，先到系统的应用管理里为 MeinKlicker 解除限制）；
2. **电池优化** → 去设置 → 允许（忽略电池优化）；
3. **自启动 / 后台运行** → 去设置 → 允许 MeinKlicker 自启动、后台运行；
4. 在最近任务里把 MeinKlicker 下拉**锁定**。

ColorOS / OriginOS 清理后台时可能关闭无障碍服务。如果悬浮栏消失，回主界面看服务状态，需要时重新开启。
## 使用

悬浮栏按钮：

| 按钮 | 作用 |
| --- | --- |
| ⠿ | 按住拖动悬浮栏；单击收起为小圆钮（单击圆钮展开） |
| 方案名 ▾ | 选择方案 / 新建方案 |
| ▶ | 直接运行：从第 1 步开始按循环设置执行 |
| 👆 | 进入 / 退出待命（手动触发）；待命中按钮为红色圆底。方案有触发点时可用 |
| ■ | 停止 |
| ✎ | 编辑当前方案的位置 |
| ≡ | 打开主界面 |

运行时每次点击的位置会出现一个扩散的圆圈（点击特效），可在主界面关闭。

### 新建方案

1. 打开目标应用，在悬浮栏点"方案名 ▾ → ＋ 新建方案"（或在主界面新建后点 ✎）；
2. 编辑栏：`+ 加步骤`、`🗑 清空`（3 秒内连点两次，清空全部步骤，触发点保留）、`👆 触发点`（每点一次添加一个，最多 5 个；已有触发点时为红色圆底）、`✓ 保存`、`✕ 取消`；
3. 拖动带编号的圆点到要点击的位置，**十字中心**就是点击点；红色的 "T" 是触发点（有多个时为 T1、T2…）。相邻步骤之间的连线和箭头表示点击顺序；
4. 单击圆点可以微调 X / Y 和执行前等待时长，或删除这一步 / 这个触发点（后面的自动重新编号）。标记大小为 32dp；如果挡住了下层按钮，在参数面板点「点击一次」，就会临时隐藏标记和编辑栏，在十字中心点击下层应用一次，方便继续设置下一步；
5. 点"保存"。

在主界面点方案可以设置名称、循环次数（或无限）、轮间隔、每个触发点的触发后延迟和触发区半径，以及每一步的等待时长；也可以复制、重命名、删除方案。

### 直接运行

选好方案，点 ▶。步骤坐标如果落在悬浮栏上会拒绝运行，把悬浮栏拖开再试。

### 手动触发

1. 方案中需要有触发点（T），可以有多个；
2. 点 👆 进入待命，每个触发点周围出现红色半透明圆圈，👆 变为红色圆底；
3. 亲手点任意一个圆圈里的目标按钮：App 会把这次点击补发给下层应用，然后自动执行后续步骤；
4. 执行完（或点 ■ 停止）后自动回到待命，所有圆圈都可以再次触发；再点 👆 退出待命。

所有触发点共用同一组步骤，触发后延迟用被点中的那个触发点的设置。触发点不计入循环：循环 3 次时，触发点只点 1 次，后续步骤执行 3 轮。补发会比直接点击多几十毫秒的延迟。

## 从源码编译

需要 JDK 17 和 Android SDK（compileSdk 34）。Android Studio Iguana 及以上可以直接打开项目根目录，等 Gradle Sync 完成后点 *Build → Build APK(s)*。

命令行：

```bash
# 1. 在项目根目录写 local.properties，指向本机 Android SDK（Windows 路径用正斜杠）
echo "sdk.dir=/path/to/Android/Sdk" > local.properties

# 2. 使用 JDK 17，例如 Android Studio 自带的 JBR
export JAVA_HOME="/path/to/Android Studio/jbr"

# 3. 编译 / 测试
./gradlew assembleDebug          # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest
```

首次编译会从 Google / Maven Central 下载依赖。

发布签名（可选）：在 `local.properties` 加一行 `release.signing=/path/to/release.properties`，该文件写上 `storeFile`、`storePassword`、`keyAlias`、`keyPassword`，然后 `./gradlew assembleRelease`。没配置时 release 包不签名。密钥和密码不要放进仓库。

### 用 adb 安装

1. 手机：设置 → 关于手机 → 连续点"版本号"打开开发者选项；
2. 开发者选项里打开 **USB 调试**。ColorOS 上还要打开"**禁止权限监控**"，否则 `adb install` 可能被拦截；
3. 用数据线连电脑，在手机上允许 USB 调试授权，然后：

```bash
adb devices                                              # 能看到设备
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb logcat -s MeinKlicker                                # 查看日志
```

用 adb 安装不受"受限制的设置"影响。

注意：debug 包和 release 包、以及不同电脑编译的 debug 包签名都不同，相互覆盖安装会失败，需要先卸载旧版本（方案数据会一起删除）。

## 工作原理

- 点击通过无障碍服务的 `dispatchGesture()` 执行，所有悬浮窗（控制栏、标记、触发区）也由无障碍服务托管；
- 手动触发采用"拦截 → 补发"：触发区先接住你的点击，随即变为不可触摸，再在同一位置补发一次点击给下层应用，然后执行后续步骤。补发会比直接点击多几十毫秒；
- 方案保存在应用私有目录的 `schemes.json` 中。
