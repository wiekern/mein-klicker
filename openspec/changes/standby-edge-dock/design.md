# Design

## Context

无障碍服务管理控制栏和触发窗，运行状态机管理空闲、待命和运行之间的切换。触发窗画成圆形，实际触摸窗口为矩形。位置计算沿用屏幕绝对坐标。

## Goals / Non-Goals

- 在进入待命前完成避让，并提供停止和退出入口。
- 待命避让属于控制栏与服务的职责。直接运行沿用自身预检，编辑器继续使用已有折叠交互。

## Decisions

1. **临时替换悬浮窗。** 在服务中构造方案障碍区域。检测到冲突时，控制栏以固定 48 dp 的独立按钮代替原栏。原窗参数和展开状态保留在内存里，退出后恢复。
2. **以实际覆盖区域避让。** 触发区使用窗口矩形，点击点使用 1 像素矩形，检测区使用原始选区。贴边位置从系统安全区内的左右两侧选择。对每侧检查原纵坐标与障碍边缘形成的候选位置。
3. **由状态驱动按钮和恢复。** 服务确认可避让后再进入待命。运行中按钮执行停止，待命中执行退出。状态回到空闲时恢复原栏。当待命方案或悬浮栏边界变化时，服务重新检查冲突。
4. **无空位时保持空闲。** 按钮需要完整可点，避免挡住触发区或下层点击。搜索失败时保留原栏，并提示用户调整区域。

## Risks / Trade-offs

- 屏幕边缘空间不足时需要用户调整方案区域。系统安全区、显示尺寸与触摸分发的表现依赖设备，需以设备验收覆盖。
- 方案格式沿用当前存储结构，无需数据迁移。
